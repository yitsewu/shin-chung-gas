# 欣中天然氣使用指南

[回首頁](../README.md) · [雲端爬蟲檢查](live-check.md)

## 安裝與新增帳戶

需要 HA 2026.9.1 以上及 Recorder。從 HACS 自訂儲存庫安裝或使用 Release 的 `scgas.zip`；ZIP 內容直接放入 `/config/custom_components/scgas/`，不要多套一層 `scgas` 目錄。重新啟動後，於「設定 → 裝置與服務 → 新增整合」搜尋欣中天然氣。

輸入帳單六碼戶號（保留開頭零）與戶名、自訂顯示名稱及歷史上限。送出時會實際查詢；成功後建立帳戶並保存帳單。不同戶號可以各自新增帳戶；同戶不能重複新增。重新設定用於修正同戶姓名或顯示名稱，不能換成另一戶號。

## 自動排程

於欣中整合的選項設定：

| 選項 | 預設 | 行為 |
| --- | --- | --- |
| 自動查詢 | 開啟 | 關閉後取消下次定時查詢；仍可手動查詢 |
| 排程 | 每週 | 可選每日／每週／每月 |
| 查詢時間 | 09:00 | HA 設定的本地時區，精確到分鐘 |
| 星期 | 0 | 0 星期一至 6 星期日；只在每週模式生效 |
| 每月日期 | 1 | 1–31；超過當月天數時使用月底 |
| 歷史上限 | 0 | 0 為全部可查帳期，正整數只取最近 N 期；不刪既有歷史 |
| 分攤方式 | equal | 依涵蓋月份平均，或 days 按天數 |
| 碳排係數／來源 | 未設定 | 必須同時填寫係數與來源才計算估算 |

例如每月 31 日 09:00，九月會在 30 日執行；每日 09:00 就不看星期或每月日期。請在 HA「設定 → 系統 → 一般」確認時區，並以「下次查詢時間」驗收設定。

定時查詢更新選定的歷史範圍，也會刷新已保存帳單的修正資料。手動操作不改變固定日曆排程。同一帳戶已有查詢進行時，另一個請求不會同時執行；手動請求回 `busy`，定時請求跳過該次。沒有自動立即重試，避免持續打向官網。

HA 停機期間不執行；重新載入後計算下一次時間，不補跑所有錯過時段。若首次歷史尚未完整，啟動時會嘗試完成首次回填。中斷中的舊查詢會標為 `interrupted`。最近 100 筆查詢紀錄記錄觸發原因、開始／結束、結果與固定錯誤代碼。

## 帳單、感測器與統計

最新帳單感測器的屬性包含白名單帳單欄位；費用與日期另有獨立感測器。使用度數是本期用氣，抄表度是累積讀值。平均每日用氣是帳期用量除以涵蓋天數，平均單價是合計除以用量；缺值或分母零不臆造數字。

「查詢狀態」與「欣中驗證狀態」反映官方查詢；「長期統計狀態」獨立反映背景統計工作。`pending`／`running` 表示尚未完成，`published` 表示已發布，`partial` 表示沒有完整可發布資料，`failed` 表示需重建或檢查 Recorder。失敗不會把已保存帳單改為零。

年度摘要只彙總已涵蓋月份；請同時檢查涵蓋月份數，不將局部歷史當全年。來源未設定碳排時保持未知；係數單位為 kgCO2e/m³，來源請填採用的公告或報告及年份。

## 月度估算與能源面板

`equal`：帳單總量平均分到每個涵蓋月份，再平均分到該月份內被帳單涵蓋的日期。`days`：先按整個帳期涵蓋日數平均，再加總為月份。例如 1 月 1 日到 2 月 28 日共 59 天、用氣 59 m³，equal 為每月 29.5 m³；days 為一月 31、二月 28 m³。兩者都保留原帳單總量，不能當成實際每日用氣。

費用直接分攤官網合計，不再把追收、退還或租金重複相加。計費起迄日皆計入；應收月份與分攤月份可能不同。重抓有更正的帳單或切換分攤選項後，背景工作重建本帳戶的統計，避免重複累加。

等待統計完成後，到能源面板設定天然氣來源，選擇「欣中天然氣 總用氣量」和對應「欣中天然氣 總費用」（自訂名稱時前綴跟隨變更）。不需建立 helper。不要把「本期使用度數」當每日累加量：它沒有累積 state class，歷史能源資料由外部統計提供。

統計 ID 為 `scgas:<entry_id>_gas`、`_cost` 與可選 `_carbon`。本整合只重建本 entry 的統計。沒有即時流率、漏氣偵測、關閥、繳費或自報度數功能。

## 手動操作與 Actions

裝置頁提供立即查詢、歷史回填與重建統計按鈕。開發者工具 → 動作可使用下列服務；先以欄位選擇器選取自己的欣中帳戶，取得實際 `config_entry_id`。

```yaml
action: scgas.get_history
data:
  config_entry_id: YOUR_ENTRY_ID
  limit: 50
```

回傳已保存帳單和月度估算，不向官網送出請求；`limit` 為 1–200。

```yaml
action: scgas.get_query_history
data:
  config_entry_id: YOUR_ENTRY_ID
  limit: 25
```

回傳最近查詢紀錄，最新在前；`limit` 為 1–100。

```yaml
action: scgas.query_month
data:
  config_entry_id: YOUR_ENTRY_ID
  month: "2026-08"
```

此例只示範格式，須換成官網仍提供的**應收帳期**，不是任意分攤月份。該操作重新查詢並更新指定一期，保留其他帳單。

## 常見問題

| 狀況／代碼 | 檢查與處理 |
| --- | --- |
| `cannot_connect` | 檢查 HA 到官網的 DNS、TLS 與網路；保留最後成功資料，稍後手動再試 |
| `upstream_rejected` | 未取得可用帳單；確認官方人工查詢是否成功及戶名是否一致 |
| `site_changed` | 網站格式、身分比對或資料解析閘門失敗；回報版本與固定代碼，不貼原始回應 |
| `duplicate_month` | 同一應收月出現多筆；為避免覆蓋而停止，需先調整資料模型 |
| `month_unavailable` | 指定月份不在官網可查範圍；用已保存歷史查詢，不捏造新資料 |
| `busy` | 等當前查詢完成再操作 |
| `interrupted` | 前一次查詢被重啟中斷；確認現況後手動查詢 |
| 查詢成功但能源沒有資料 | 檢查統計狀態、Recorder 與能源選取來源，再按重建統計 |
| 繳費期限／碳排未知 | 可能是官網省略期限，或未設定碳排係數；不是零 |
| 舊帳單尚未顯示已繳 | 使用歷史回填刷新；已銷帳不代表可推論付款渠道或付款日 |

真實未繳帳單、換表及同月多筆的所有形狀尚未完整驗證。公開徽章通過只證明測試帳戶在 GitHub 網路上查詢成功，不能取代自己的 HA 狀態。

## 更新、備份與移除

更新前使用 HA 備份，包含設定、Store 與 Recorder。HACS 更新或覆蓋整合程式後依提示重啟；保留原 config entry 即保留帳戶識別。不要手動刪除整份 `.storage` 或 Recorder 資料庫。

暫停抓取可先關閉自動查詢；需停用整合則在裝置與服務操作。移除 entry 不主動清空本機歷史 Store 或外部統計；再次新增可能取得不同 entry ID。復原優先恢復同一帳戶的備份，避免建立重複能源來源。沒有自動清除個人歷史功能，清理前應先確認備份與需要保留的統計。

問題回報附上整合／HA 版本、觸發方式、時間、固定錯誤代碼與去識別診斷；不要附戶號、戶名、住址、金額明細、Cookie 或完整帳單。
